# PR17：录音收尾与模型错误呈现

## 录音路径与审查修复

主窗口按实际语音状态（加载、采集、转录）和临时手动模式显示操作区，不只依赖常驻麦克风开关，也不因此改写已保存偏好。主窗口和 HUD 共用 can-finish-recording / can-cancel-recording 条件，Agent 忙碌或等待审批时禁用这两个操作；语音确认依然通过原有自然端点和审批路由完成。

结束录音使用独立命令，绑定实例号与句号。点击立即显示“正在结束录音”，通过 finishing 状态抑制双击，不提前消费回合令牌。worker 核对活动回合；忙碌路径拒绝并恢复 finishing，终止状态、Final、Rejected 和取消清理令牌。取消识别只丢弃当前输入，不取消 Agent 工具任务。

音频线程沿用 ActiveSession::request_finish、队列快照、重采样与不足一帧 PCM 收尾，并复用 SessionMachine::finish。自然端点和人工收尾只能消费一次 session，旧回合请求无法结束新回合。Final/Rejected 沿用 ListenPurpose、审批请求号及 Session 归属处理，临时麦克风恢复原偏好。没有新增 unsafe 或依赖。

不采用停止 VoiceHandle 实现提交，因为停止会取消 ASR；控制请求仍存在音频线程轮询与消息调度延迟。

## SSE 与错误说明

consume_stream 和 pump_event 共享事件名与解析后 JSON 字段的错误规则，移除文本包含 error 的猜测。显式 event:error / event: error 或非空协议 error 字段及时失败；error:null、正文字符串中的 JSON/代码以及无效 JSON 片段不被误认成服务错误。保留 UTF-8 与网络分片缓冲和原有工具完整性判断。

错误说明提取真实 code、type、message 或字符串 error。HTTP 状态取自真实响应；连接、超时、协议与断流错误不虚构状态。保留 llm_error / stream_error 等内部分类，通过 failure_message 展示脱敏说明；AgentEvent::Failed 与最终说明一致。实际 Key、认证内容、敏感 URL、超长字段与控制字符不原样写入 Session。取消仍按原语义处理。

状态栏和系统时间线使用同一份说明；HUD 同步状态栏，Session 沿原保存流程持久化。没有自动重试、工具伪结果或额外权限。
