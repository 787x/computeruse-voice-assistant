### R1 · 内置本地备用轻量模型（可手动切换）
- 原文：「软件需要内置本地备用轻量模型（可手动切换）」
- 影响面：方案 v0.2 的「五、语音链路」与「四、目录结构」需新增本地推理进程；打包体积、模型分发、切换 UI、降级策略全部要设计。
- 待定问题：
  - 模型选型（参数规模 / 量化 / license）
  - 运行时（llama.cpp 二进制内置 vs ONNX Runtime vs 其他）
  - "备用"的触发条件：手动切换 only，还是断网/超时自动降级
  - 本地模型是否也要支持 tool calling（computer-use 需要 function calling，这是硬门槛）

- 原文：「我认为高风险可以语音确认」

## 变更项（第二批，2026-10-27）

### R5 · 语音唤醒可关闭
- 原文：「语音唤醒可关闭」
- 含义：用户可完全关闭唤醒词监听；关闭后应**释放麦克风采集流**（不只是停止识别），托盘麦克风指示随之消失。
- 降级路径：关闭唤醒 → 仅保留全局热键（按住说话）。
- 待定：关闭后是否保留"热键说话"？—— 建议保留，两者解耦（唤醒 ≠ 采集）。

### R6 · TTS 可关闭
- 原文：「tts 可关闭」
- 含义：静默模式，助手只出文字不出声。
- **连带影响（重要）**：TTS 关闭后，高风险操作**无法再用语音确认**（因为无法提问）。此时必须自动降级为 HUD 卡片物理确认。这是关闭 TTS 的隐含代价，需在 UI 上明示。
- 待定：是否拆成两个独立开关——"语音播报"与"确认提问"？建议拆分。

### R7 · 权限可设置
- 原文：「权限可设置」
- 含义：逐项控制助手能力边界，而非全有全无。
- 待设计：权限粒度、级别（允许/每次询问/拒绝/限时）、持久化、审计日志、与系统隐私设置联动。
- 对应方案：v0.4 §6。

### R8 · 文档先行
- 原文：「先更新文档」
- 执行：产出 `07-开发方案-v0.4.md`（整合版），v0.2 / v0.3 转为历史版本。

### R9 · agent 要有配置界面（模型提供商 + 模型）
- 原文：「agent 要有配置界面，配置模型提供商和模型」
- 含义：用户可在界面里选提供商（云端/本地）、填 endpoint 与密钥、选模型，并即时生效；不是改配置文件。
- 约束：
  - 密钥不能明文回显（界面只显示掩码）
  - 支持"测试连接"，给出可读的失败原因
  - 提供商至少覆盖：DeepSeek 官方、任意 OpenAI 兼容端点、本地 llama.cpp
- 落地位置：`packages/config/`（数据层）+ 配置页（P2 起并入 Electron 设置页，当前先用本地网页验证）

### R10 · 出语音的同时要有字幕
- 原文：「出语音的同时，字幕也得有」
- 含义：语音播报与字幕必须同步，不能"先把整段说完再显示文字"。
- 关键设计（详见 `08-UI规范与字幕同步.md`）：
  - 流式切句 → 句子落地即同时出字幕与 TTS
  - 句边界精确（由音频时长驱动），句内逐字高亮按字数插值（TTS 无词级时间戳）
  - 用户自己的话也要显示（ASR 部分结果灰色上屏）
- 验收：**关掉声音只看字幕能跟上**，且**只听声音不看屏能听懂**。

### R11 · UI 全权借鉴本机 Microsoft Copilot
- 原文：「UI 什么的全权借鉴微软 copilot，就我之前跟你说我本机上装的那个」
- 执行：实拍本机 Copilot 156.0.4314.42（`docs/assets/copilot-reference.jpg`），提取设计令牌。
- 结论：浅灰白 + 药物形输入 + 无边框分层 + 标题不加粗 + 单一强调色。
- 落地：`08-UI规范与字幕同步.md` 的 §1 设计令牌、§3 浮层形态。
- 未覆盖：Copilot 语音会话页（需登录态，未拍到），聆听/播报态为设计语言外推。

### R12 · 只要右下角小窗，不要大窗口
- 原文：「我不需要那种大窗口，我只需要能从右下角弹出一个小窗口，不遮我的工作内容，倾听并回复」
- 含义：**否决** v1 的"320×56 底部居中胶囊 + 向上展开到 720×560 卡片"。
- 新形态：常驻右下角，展开 380×自适应（最大高 420），**宽度固定不长**。
- 硬要求：不抢焦点 / 不入任务栏 / 按 workArea 定位 + DPI 换算。
- 落地：`08-UI规范与字幕同步.md` §3（已重写）。

### R13 · 没被叫就不该有任何页面
- 原文：「不叫他，他就没有任何页面，只有在点击托盘里面的图标或者语音唤醒之后，才会出现这个小窗页面，所以不需要什么鼠标穿透」
- 含义：
  - **否决** R12 里的"收起态胶囊"和"待命态鼠标穿透"——因为平时根本没有窗口。
  - 进程常驻只有托盘图标 + 后台唤醒监听。
  - 触发只有两种：托盘图标点击（show 并聚焦）/ 语音唤醒（showInactive 不抢焦点）。
  - 对话结束静默 8s 自动隐藏，回到"无窗口"状态。
- 落地：`08-UI规范与字幕同步.md` §3.2 生命周期、§3.5、§3.6 托盘菜单。

### R14 · 窗口隐藏 + 游戏/内存紧张时销毁
- 原文：「隐藏，然后检测到游戏进程的时候，或者内存紧张的时候销毁」
- 决定：
  - 默认 `hide()`（唤出 <100ms）
  - 全屏独占应用运行中 / 系统可用内存 <1.5GB / 自身 RSS >400MB → `destroy()`
  - 销毁后托盘与唤醒监听仍在主进程，下次唤出重建（~200ms）
  - 退出游戏**不自动重建窗口**
- 检测手段：`SHQueryUserNotificationState`（本机已验证可调用）+ `os.freemem()`
- 落地：`08-UI规范与字幕同步.md` §3.8

## 阶段性结论（已实测，供 v0.4 引用）

| 项 | 结论 |
|---|---|
| `cua.ps1` 握手 | ✅ 通过，dpiAware=true，2560×1600 @144DPI，冷启动 ~1050ms |
| 截图参数 | 必须 JPEG q70@1024（197ms），PNG 全屏 1379ms 不可用 |
| 音色 | 定稿 `vits-zh-hf-bronya` + 重音压缩 beta=0.0 / 限幅 ±22dB（动态 31.5→15.8dB） |
| 音高压平 | ❌ 弃用（WORLD 重合成掉高频，听感变哑） |
| 麦克风共享 | ✅ 双进程并发采集互不影响（WASAPI 共享模式） |
| 麦克风电平 | ⚠️ 阵列实测 -49.6 dBFS，必须做 AGC |
