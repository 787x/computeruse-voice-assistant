# PR13 审查修复与验证记录

## 范围与设计

沿用供应商实例、SecretStore、模型发现、Session 和 Slint UI，不改 PR12 工具系统，不实施 PR14 TTS。

凭据授权只针对实例与确切 Base URL：测试连接、获取目录和保存共用同一个检查。相同已保存端点可留空复用 Key；新地址需输入新 Key，或点击明确的复用按钮。确认绑定确切地址，编辑 URL 或 Key 后作废。工作线程保存时再按权威配置检查，不能由排队的旧草稿绕过。保存后 Agent 沿用同一实例的配置与 Key，因此不需要新增权限审批状态机或额外凭据数据库。

父快照与卡片本地草稿分开。Slint 对结构字段赋值会解除单向绑定，原实现因此可能在编辑后不再显示异步结果。现在父快照变化显式回填本地草稿；模型展开和启用切换通过卡片动作更新对应模型。保留草稿代次校验，旧请求不能覆盖后续编辑。

模型来源地址进入卡片往返和持久化。改变 URL 时，只降级服务端模型及其元数据，不清空手动条目、启用列表或默认选择。目录中消失的模型保留为可编辑的未验证条目；刷新失败不合并。获取请求只读取端点和凭据，不要求草稿模型行完整；保存仍拒绝空 ID 和重复 ID。

模型分组以实例 ID 为身份，显示名只作标题。同名标题附带地址和 ID。Key 存在性覆盖全部配置实例，启动、保存、清除和删除后刷新，不修改 Session 模型选择。

模型支持的最大输出量与请求预算分开。默认请求不因目录声明而注入 max_tokens；有显式请求预算时取预算与模型能力的较小值，连接测试的 16 tokens 预算同样受能力约束。

删除检查全局默认、方案 provider_id（覆盖时段规则通过方案的引用）、Session modelChoice.providerId 和当前会话选择。正文、历史消息来源和工具日志不代表当前模型选择，不阻止删除。配置或 Key 删除失败有明确错误并尽力恢复原配置，不重绑其他端点。

## 自动化测试

本轮新增和扩展的测试覆盖：

| 问题 | 验证 |
| --- | --- |
| URL 与 Key 绑定 | 未确认改变 URL，resolve_key 和保存都拒绝；本地监听器未收到连接；新 Key 或确切 URL 确认可用；再次改地址需重新确认 |
| 同协议多实例 | 五个本地 HTTP Mock 校验独立 URL、Authorization、model、MiMo thinking、DeepSeek reasoning 和纯兼容字段 |
| Key 状态 | 自定义实例添加与清除 Key 后逐实例刷新，Session 选择保持不变 |
| 同名分组 | 两个同名实例 ID、标题不同，真实模型选择处理函数选择第二实例，Session 重读仍绑定第二实例 URL |
| 目录来源 | 地址变化后旧服务端元数据清空为未知，来源降级；手动字段与启用项保留；来源往返一致 |
| 输出预算 | 三协议无显式预算时均不发送 max_tokens；显式预算只被模型能力收紧 |
| 空白行 | 端点请求可由 header 构造；合并保留未完成行、手动字段、启用集合和服务端消失条目；保存仍报空 ID |
| 结构化删除 | 正文和方案名称包含 ID 可删除；真正 Session 或方案引用拒绝 |
| 保存失败 | 临时配置提交路径被阻塞时，原配置文件不变，原 DPAPI Key 恢复 |
| 重启恢复 | 五实例配置与 DPAPI 隔离、模型元数据、Session 选择重读验证 |

默认 CUDA Windows build、fmt、clippy 已运行。库测试最终记录及相关集成测试结果见本记录末尾；没有构建 CPU-only 版本。既有 TTS 缺失模型测试在本机存在模型时不满足其环境前提，仍单独跳过，不修改该历史测试。真实麦克风测试保持原忽略标记。

## Windows GUI 实测

使用 rust/target 下隔离数据目录，不读取用户实际 Key 或配置。局部连接测试使用本地 HTTP 服务与无真实权限的测试字符串，未访问真实供应商服务。

已实际操作：

- 默认 MiMo、DeepSeek 展开和卡片滚动；添加额外 MiMo、DeepSeek、兼容端点草稿。
- 第二份 MiMo 独立保存并在重启后保留；其他未保存卡片没有写入配置。
- 中文名称文本输入和显示、Tab 从名称进入 Key 再进入测试按钮、回车激活。
- Key 同行测试按钮：普通未测、测试中、绿色成功、红色失败及行下 401 原因；修改 Key 后立即重置。
- 关闭整个设置窗口取消 URL 和 Key 草稿，重新打开恢复原地址和空 Key 输入。
- 200% 应用缩放下滚动、模型展开、高级上下文编辑为 32000、单卡保存并核对实际配置文件。
- 删除确认与取消删除后保留卡片。
- 100%、150%、200% 应用缩放下观察布局。缩放通过 SLINT_SCALE_FACTOR 测试覆盖实现，不等于切换 Windows 系统 DPI。

未完成的实机矩阵：真实中文输入法候选窗与组合输入、实际 Windows 系统 DPI 切换及跨屏、所有五卡逐一完成保存/删除/重启的完整 GUI 组合、长模型名的完整 GUI 操作链。相应数据逻辑已有自动化覆盖，但不能据此声称这些 GUI 项已验收。

批量生成 GUI 配置的辅助命令曾被自动审批拦截；没有执行该批量写入，改用现有隔离配置和界面操作继续验证。

## 最终结果

- `cargo fmt --check`、默认 CUDA Windows `cargo build -j 1`、`cargo clippy -j 1 --all-targets` 通过。clippy 仍报告既有的枚举大小、参数数量和测试初始化等警告；未为消除警告重构无关模块。
- 最终串行库测试：459 通过、3 忽略、1 项环境相关 TTS 缺失模型测试跳过。
- 六组相关集成测试：57 通过（config_secrets 8、migration_and_config 9、pr12_tools 30、pr8_model_discovery 1、pr8_probe_and_cache 3、settings_save 6）。
- 五端点 HTTP 测试也实际带空白模型草稿发出 `/models`，合并后空白行仍保留；三个协议族的连接请求实际验证显式 4 tokens 预算未被 8 tokens 能力上限或默认 16 tokens 探测预算放大。
- 展开行、删除确认等纯 UI 动作不会作废进行中的连接测试；请求相关编辑会作废旧结果，避免按钮停留在过期的“测试中”。

仍需按上述实机矩阵补齐的项目，不在本记录中宣称通过。没有新增应用运行时依赖，也没有修改 Electron 配置或发布 Release。
