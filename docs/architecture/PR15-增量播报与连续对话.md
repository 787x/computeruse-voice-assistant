# PR15：增量播报与连续对话

## 安全边界与选择

沿用 Agent、UiConfirmer、Whisper、TtsEngine 和唯一播放器，不增加判断用 LLM 请求。Agent 仅在请求工具列表为空时发出 SpeechEligible，包含回合和步骤身份。正常携带工具定义的响应无法从 content delta 判断后面是否还有 tool_calls，因此仍等待完整回合结果。步数用满后的既有收尾请求不提供工具，可以提前播报；没有人为禁用原工具。

生产者使用 begin/append/finish，一个 SpeechId、连续句号和一个 Feed。合成队列最多积压 32 个句子片段，worker 另保留最多 32768 字节的待播正文，队列暂满时定时重试，回合结束后将有限尾队列交给受同一取消令牌控制的异步发送任务。Agent 不等待音频队列。只有待播正文确实超过字节上限才明确停止声音并显示提示；TTS 失败不影响 Agent。每句按引擎字节预算拆分，沿用 MiMo PCM/WAV、音色、标签、风格、语速、音量、设备和 Key 设置。finish 只关闭输入，Finished 仍以设备排空为准。

中文完整句界优先。英文仅采用保守的空白加大写后继句界，避开常用缩写、小数、URL；Markdown 使用跨分片的局部状态机：标题、强调、列表和链接文字可继续输出；URL、行内代码和围栏代码不进入句子队列。代码/链接结束后立即恢复普通句子，不设置整篇永久延迟。缺少句界的可读长段优先在空白或逗号降级，最多约 1K 字形成一块；不猜测代码含义。增量清理不再沿用完整回复的 400 字截断预算。

提前播报无法撤回已经听到的句子。后续 SSE 失败会停止剩余声音，不冲刷失败尾句；不能承诺提前读出的普通回答最终不会遇到网络错误。

## 监听与追问

连续对话默认开启但不自行打开麦克风。设置保存 continuousConversation、followupSeconds，旧配置按 serde 默认值兼容；界面可选 4/8/15/30 秒，默认 8 秒。用户启用常驻监听后，成功语音回合等待当前实际音频结束再计时；无声音或声音失败则从回合结束开始。一次临时录音不会转成常驻。

优先级为 Confirm、BargeIn、Manual、Followup、Wake。追问使用单调期限和代次作为 request_id，并沿用麦克风实例和语音回合身份。音频线程在 VAD 开始有效语音时原子登记录音准入；截止前已准入的语音可以在期限后完成 ASR，worker 消费事件较晚也不会丢失。截止后才开始的语音不能准入。取消、切会话和关麦清除准入及代次，拒绝/识别失败清理占用，沿用现有单句最长时长与识别结束路径。取消、关麦、切会话使其过期。主循环每 250ms 更新可理解的剩余时间。审批继续使用现有 request_id、oneshot 与一次授权，没有改变权限档位。

打断词单独出现只停止音频；包含新请求且 Agent 已结束时，保留正文提交同 Session。Agent 忙时取消旧任务，只有旧任务终结后才提交替代语音。最多等待 8 秒，届时明确丢弃并提示重说；Session、麦克风实例和取消代次均须匹配，不建立无期限待执行队列。

## 验证边界

假扬声器消费的仍是 PlaybackShared/Feed 正式播放链，但不证明实体扬声器音质、真实 ASR 回声隔离或本地模型推理效果。麦克风、MiMo 账号与本地 ONNX 的声学验收需单独执行。普通带工具响应无法安全承诺首句提前播放，不应宣传全部路径均增量播报。

## 审查修复：设置与主动停止

SaveAll 不再提前禁用增量输入或停止播放器。沿用现有保存事务的校验、落盘和 tts_runtime_config_changed 判断；SpeechRuntime 只有实际应用资源配置时递增修订号。成功保存且资源确实切换后，worker 才作废该回合剩余声音；无关设置和校验失败不影响声音。运行中回合使用开始时的播报策略快照。

语音打断通过同一 SpeechRuntime 的停止修订号同步给当前 IncrementalSpeech，主动停止会清除待播队列、禁止后续 TextDelta 入队，并阻止回合末尾全文回退。它是正常用户操作，不报告播放器故障；带新请求的打断仍沿用先取消再串行提交的规则。审批的 request_id、oneshot 和权限策略不变。

普通携带工具定义的 content 流依旧没有可靠的早期最终性信号，本次不增加分类/收尾请求、不关闭工具。新增时序验证经过实际 Agent 事件与 worker 增量消费器，使用现有步数耗尽后的无工具收尾；它不能证明普通带工具回答都能提前朗读。
