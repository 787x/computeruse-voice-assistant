# PR12：非音乐工具能力与本地时间

## 范围与取舍

在 PR11 的 `main` 上恢复旧 Electron 版**全部非音乐工具**能力，而不只是补几个工具名。保持现有 Agent、权限档位、工具调用时间线、Session、PowerShell CUA 与语音路径不变。音乐仍然不移植；上游 CUA 未默认暴露的 25 个动作也不恢复。

最终模型可发现的工具：

| 来源 | 数量 | 说明 |
|---|---|---|
| Computer Use | 12 | PR5 的默认白名单，行为未改 |
| 本地（旧版 6 个） | 6 | `run_shell`、`files`、`app_control`、`kill_app`、`launch_app`、`system_info` |
| 本地时间 | 1 | `get_current_time`（只读，本 PR 新增） |
| 联网搜索 | 0 / 1 | 仅在**有可用 Tavily Key** 时公布 `web_search` |

统计上必须区分「工具总数」与「条件启用数」：`ToolInventory` 把 CUA、本地、时间、搜索分开计数，`summary()` 直接给出「工具总数 N：Computer Use 12 + 本地 6 + 时间 1 + 条件启用 0/1」，设置页的「工具与联网」原样显示这句话。没有实现的工具不会显示为可执行——总览列表与 `tool_definitions()` 同源（都来自 `ToolRegistry`）。

## 为什么不在 `cua.ps1` 里加动作

`cua.ps1` 的协议是「一次一条命令 + 一条 NDJSON 响应」，用于**界面控制**（屏幕、UIA、键鼠、剪贴板）。把命令执行、文件读写塞进那条协议会带来三个问题：

1. **取消语义冲突**：CUA 的取消是「命令已写进 stdin，状态未知」，文件动作的取消是「阻塞线程可能已经完成」。两者混在一起，就无法如实报告"到底做没做"；
2. **权限分档失效**：`files` 的 delete 必须落到 `file.delete`，而 CUA 协议没有动作级能力的概念，只能在 Rust 侧再拆一层——等于把分类逻辑复制两份；
3. **上下文与输出不可控**：CUA 的响应是为界面读优化的，`run_shell` 需要自己的超时、输出上限与退出码语义。

因此本地工具是 **Rust 原生实现**（`src/tools/`），不复刻旧 Node 代码，也不改 CUA 引擎。

## 统一分发：`ToolRegistry`

```
Agent ──> ToolInvoker（ToolRegistry）
             ├─ CuaToolkit（12 个，原样保留）
             ├─ run_shell / files / app_control / kill_app / launch_app / system_info
             ├─ get_current_time
             └─ web_search（仅有 Key 时）
```

三条边界：

- **定义只在一处汇总**：`tool_definitions()` 是模型能看到什么的唯一来源；
- **执行只在一处分发**：名称 → 实现是显式 `match`，未知名称报错，不存在"名字碰巧对上就执行"；
- **权限仍在 Agent 之前**：注册表不做任何授权判断。`PermissionGate` 先跑，被拒绝的调用根本到不了这里，所以它**不可能**成为绕过权限的旁路。

工具定义与参数宽化（数字/布尔字符串、`as_args`）与错误类型（`ArgError` / `LocalError` / `ToolError`）都已挪到 `src/tools/{spec,error}.rs`，CUA 与本地工具共用同一套形态；`cua::ToolSpec` / `cua::ToolError` 重新导出，既有调用点不需要改动。

组合之后，取消语义也保持了一份：`ToolError::is_cancelled()` 对 `BridgeError::Cancelled` 与 `LocalError::Cancelled` 返回真，Agent 据此写"已中断（状态未知）"而不是"未执行"。

## 本地时间的两条路径

旧版的代价值得记下来：模型为了"现在几点"去调 `run_shell`（`Get-Date`），而 `system.shell` 在标准档是**每次询问**——屏幕上会弹出一张确认卡，用户没理它，等满拒绝超时，一轮对话白等三分钟（审计日志里有记录）。

因此分两层，**都不经过 LLM、不需要 Key、不需要 CUA 后端**：

1. **直接回答**（`clock_tool::try_direct_answer`）：在 `UiCommand::Send` 与语音最终文本两处入口先判断，命中「现在几点 / 今天几号 / 星期几」就用 `clock.rs` 回答，走与正常回合**相同**的收尾（写时间线、落盘、播报、状态复位）。
   识别刻意比旧版严格：含"天气/新闻/股价/日程/限流/油价…"的说法一律交给模型，避免把"今天天气怎么样"截成一句时间。
2. **只读工具**（`get_current_time`）：给复杂任务用，返回本地日期、时间、星期、时区偏移与 Unix 毫秒。能力是 `none`（默认放行，不弹确认）。

两条路径都**绝不**让模型猜系统当前时间。时区偏移来自 `GetTimeZoneInformation`（含夏令时 `DaylightBias`），失败时如实显示 `UTC` 而不是编一个看起来合理的偏移。

`clock.rs` 新增 `spoken_time` / `spoken_date`，与旧版 `formatTime` / `formatDate` 逐段对齐（`0–5` 凌晨、`6–11` 上午、`12` 中午、`13–17` 下午、`18+` 晚上；整点说"整"）。

## 权限映射

| 工具 | 能力 | 默认级别 |
|---|---|---|
| `run_shell` | `system.shell` | ask |
| `web_search` | `web.search`（新增，留痕） | allow |
| `get_current_time` | `none` | allow |
| `app_control` / `system_info` | `window.read` / `system.info` | allow |
| `launch_app` | `app.launch` | allow |
| `kill_app` | `app.close` | ask |
| `files` list/read/info | `file.read` | allow |
| `files` write/copy/move | `file.write` | ask |
| `files` delete | `file.delete` | ask |

`files` 的分级在 `permissions::classify` 里按 `action` 决定，**删除永远不会落到读取能力下**。action 解析做大小写与空白收敛；漏 `action` 时归到 `file.read`，但那次调用会在执行前被参数校验拒绝——最坏结果是"一个本来就不会执行的调用按读取放行"，不会造成写入或删除。

只读工具（时间、系统信息、进程列表、文件读取、搜索）在标准档**不需要逐次确认**：这是"不为安全增强牺牲日常便利"的落点。四档（含免确认）、逐能力覆盖、全局暂停与审计全部照旧生效，未知工具在任何档位都拒绝。

## 执行与取消

- `run_shell`：Windows PowerShell 5.1、`-NoProfile -NonInteractive`、stdin 为 null；默认 30 秒、最多 120 秒；输出截断到 4000 字并写明原始字节数；退出码如实返回。
- 超时与取消都用 `taskkill /F /T` 终止**整棵进程树**（只杀 `powershell.exe` 会留下它启动的子进程）。超时的结果文本明确写"可能已有部分副作用、终止不会撤销已发生的变更"，**不**说"未执行"。
- 取消时 `run_powershell` 返回 `Cancelled`，Agent 按"已中断（状态未知）"处理——这与 CUA 的取消语义一致。
- 文件 I/O 与 CPU 采样都走 `spawn_blocking`，不在 Slint 线程或 async worker 上阻塞。
- `kill_app` 绝不结束当前主程序、自己的 CUA 子进程或语音/ASR 进程：判定用**路径**（可执行文件所在目录、`CUAVA_DATA_DIR` 等），因为「名字叫 python.exe」既可能是用户的、也可能是我们自己的。
- `system_info` 直接调 Win32（`GetSystemTimes` / `GlobalMemoryStatusEx` / `GetDiskFreeSpaceExW` / `GetSystemPowerStatus` / `GetTickCount64` / 注册表版本号），几毫秒完成，不需要 PowerShell 子进程。拿不到的字段（台式机无电池、无权限的分区）明确写"无法获得"，不留空也不写 0。

## Tavily

- 端点写死 `https://api.tavily.com/search`，`POST`，`Authorization: Bearer <key>`；body 里**不再**带 `api_key`（旧版那样做会被当前接口拒绝）。
- Key 存在 `SecretStore` 的**独立槽位** `web-search`，与任何模型提供商互不影响：`load_search_key` / `save_search_key` / `clear_search_key` 是一组单独的入口，`masked_keys(&provider_ids)` 也不会把它列成一家提供商。
- 没有有效 Key 时 `web_search` 不出现在 `tool_definitions()` 里；`enabled()` 只看 Key，不看网络。填好 Key 保存后调用 `set_api_key` **原地生效，不需要重启**，同时清空缓存并推进 `revision`。
- `query` / `max_results`（1–8，默认 5）/ `search_depth=basic` / `include_answer=true`；单条摘要截断 320 字、保留来源 URL、结果条数上限 8；同查询 + 同条数 5 分钟内命中缓存（容量 32，超了清最旧一半）。
- 超时 8 秒、可取消（请求体与响应体读取都可中断）；401/403、429、5xx 分别给出可照做的说明。网络失败只影响这一次调用，本地工具不受影响。
- 返回给模型的文本只有「查询 / 要点 / 来源 + 摘要」，不把网页正文或 Key 塞进上下文。
- 设置页「工具与联网」提供 Key 输入、启用开关、可用性测试（真实打一次）、清除 Key 与状态提示；测试在后台任务里跑，不在 Slint 线程上等。

## 设置与可发现性

设置新增第 6 个分类「工具与联网」，包含：

- **可用工具总览**：逐行 `✓/× 名称 · 来源 · 只读/可执行`，不可用的写明原因（缺 `cua.ps1`、缺搜索 Key）；这句清单与实际请求里的 `tools` 同源。
- **工具总数与构成**：区分无条件可用与条件启用。
- **Tavily 配置**：Key、启用开关、测试、清除、边界说明（第三方、计费、不复用模型 Key）。
- **帮助文本**：`run_shell` 与 Computer Use 的区别、Tavily 的联网与收费边界、时间问题的离线回答。

## 验证

- `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`（Rust 单元与集成）。
- 真实 Windows 上执行：只读 PowerShell、列目录、写/读/重命名/删除临时目录文件、按名字查应用、进程查询、系统信息、日期时间。
- 权限：拒绝 `run_shell` 与拒绝删除时**实际执行计数为零**；允许后结果回到同一 Agent 与工具时间线；`files` 的 read/write/delete 分别判定；标准/免确认/暂停/覆盖/语音确认不回归。
- 超时与取消：不把"可能已发生副作用"说成"未执行"。
- Mock Tavily：Bearer 认证头、请求体参数、摘要与来源、401/429/超时、取消、换 Key 后的可用性。真实 Key 与收费接口不作为自动测试前提。
- 时间：系统时区变化时结果正确，且不需要网络。
