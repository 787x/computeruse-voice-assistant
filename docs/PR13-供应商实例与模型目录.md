# PR13：供应商实例与模型目录

## 设计决策

供应商实例 ID 是凭据、会话与模型方案的持久身份；协议族是独立的 `protocolKind`。历史 `mimo`、`deepseek` ID 保留。新增实例使用带时间戳的独立 ID，改名称和 URL 不改变身份。MiMo、DeepSeek、OpenAI-compatible 都复用原请求适配，不通过显示名称或 URL 推断协议。

旧配置未带协议族时，按历史内置 ID 或显式 `providerHint` 迁移；规范化后保存明确的协议族。此后 hint 不再改变协议。没有引入 unsafe、WebView、额外进程或新推理引擎。

替代方案是继续使用三个固定索引，或把额外 MiMo 实例伪装成兼容端点；两者都会将实例身份与协议混淆，因此没有采用。配置保留 `id` 字段的序列化名称，避免会话、密钥文件及历史方案迁移成本。

## 使用方式与保存边界

模型页顶部选择协议类型并添加供应商。MiMo 与 DeepSeek 初始展开，内容在整个设置页内滚动。卡片显示稳定实例 ID，供模型方案引用；名称可修改。每张卡编辑自己的地址、Key、默认模型、推理档位和模型目录。

卡内保存独立提交，取消恢复该卡已保存内容；新建但未保存的卡取消时移除。窗口底部保存仍处理其他设置。已成功独立保存的卡不因关闭窗口而撤销。

Key 留空使用本实例已存凭据；新实例不会借用同类型其他实例的 Key。连接状态只来自真实连接测试，地址、名称、Key 和模型修改会使状态变未测。保存请求中的 Key 使用已有脱敏草稿类型，避免 Debug 输出凭据。

删除要再点一次确认；被全局默认、模型方案或已保存会话引用时拒绝并说明原因。用户先更换引用后再删除。内置卡删除后记录在 `removedProviderIds`，避免重启时从注册表自动复活。定时规则通过方案间接引用，方案引用检查覆盖该路径。

## 模型与元数据

每行有模型 ID、显示名和启用状态，展开后可编辑上下文窗口、最大输出 tokens 与图片输入能力。未知数值用空值表示，图片能力默认未知，不根据模型名称推断。文本是当前聊天协议的基础输入。

上下文元数据沿用现有只收紧窗口预算的逻辑。最大输出写入真实请求的 `max_tokens`。明确配置不支持图片时，请求中移除图片段并保留文本。未知能力仍沿用原请求行为，不伪造视觉声明。

目录刷新使用卡片草稿 URL 与该实例 Key。请求在独立短任务线程执行，复用已有模型发现与连接测试函数。完成时检查实例、地址、Key、模型、完整配置及草稿代次，拒绝过期回填。手动模型与手动元数据优先，失败保留目录。

恢复默认只替换本卡的草稿目录和默认模型；URL、Key、其他卡与已保存会话不变，需保存才落盘。默认模型必须存在于启用目录，删除默认行会提示先指定替代模型，禁用默认项不能保存。

## 风险与后续扩展

当前连接测试结果不持久化，重启回到未测。目录服务未知的图片能力保持未知。恢复默认采用注册表现有模型，不复制参考图中的模型能力或上限。

读取会话文件失败时删除失败，不绕过引用检查；会话引用扫描采用保守字符串检查，可能拒绝存在同一 ID 文本的会话，避免误删。后续可将扫描收紧为结构化会话引用索引，但本次不引入索引维护架构。

配置写盘失败时会恢复本实例原 Key；若恢复也失败，错误信息明确报告。内置 MiMo Key 更新继续刷新已有 MiMo 播报引擎。每张卡的清除 Key 按实例 ID 提交，移除了旧固定索引的全局清除按钮。
