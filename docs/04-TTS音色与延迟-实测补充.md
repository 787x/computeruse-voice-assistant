# 补充实测 · TTS 音色与延迟（回答「能实现低延迟的自定义音色吗」）

> 数据来自 2026-10-27 实测，脚本：`tools/bench_local_tts.py`、`tools/bench_tts.mjs`、`tools/check_tts_chunks.py`

## 一、结论

**能，但不能沿用 v0.3 里的 edge-tts 那一层。** 必须把 L1 换成**本地神经 TTS**——实测它比 edge-tts 还快，且离线。

v0.3 的三层方案有个我当时没点破的缺陷：**L0 用你的音色渲染、L1 用 edge-tts 的固定音色，一句话里会出现两个不同的人**。你这个问题正好戳在它上面。

## 二、实测：本地神经 TTS（sherpa-onnx + VITS 中文多说话人）

模型：`vits-icefall-zh-aishell3`，**29.8 MB，174 个说话人**，纯 CPU 推理（16 核），不占显存。

| 用例 | 首包 | 总耗时 | 音频时长 | 实时因子 |
|---|---|---|---|---|
| 短句 11 字（冷首次调用） | 424.9 ms | 445.7 ms | 2.95 s | 0.151 |
| 中句 23 字 | **130.7 ms** | 146.5 ms | 7.10 s | **0.021** |
| 长句 29 字 | **137.4 ms** | 154.9 ms | 7.97 s | 0.019 |
| 热状态重复调用 | — | 140.3 / 134.2 ms | — | — |
| 模型加载 | 1336 ms | — | — | — |

### 对比 edge-tts（云端）

| 方案 | 首包 | 网络 | 音色 |
|---|---|---|---|
| edge-tts | 339–351 ms | 必需 | 固定，不可定制 |
| **本地 VITS** | **125–140 ms（热）** | 不需要 | 174 选 1，非克隆 |
| L0 预渲染 | ~0 ms | 不需要 | 完全自定义（离线任意渲染） |

**本地比云端快 2.5 倍，还离线。** 实时因子 0.02 意味着：1 秒语音只要 20ms CPU，算力余量巨大——甚至可以边播边算下一句。

> 口径说明：回调是**句级分块**（progress 0.5 → 1.0），不是采样级流式。首包 130ms 已足够覆盖"开口即出音"，但如果要做更细粒度，需要换流式模型架构。

## 三、"自定义音色"的三个档次（差别很大，别混为一谈）

| 档次 | 实现 | 延迟 | 成本 |
|---|---|---|---|
| **选音色** | 多说话人 VITS（174 个内置音色，`sid` 切换） | 130 ms ✅ 已实测 | 零 |
| **克隆音色（零样本）** | CosyVoice2 / F5-TTS / GPT-SoVITS，1 分钟录音 | **[未验证]** 500ms–2s 量级，需 GPU | 模型 0.3–2 GB |
| **专属音色（微调）** | 用自己 30 分钟录音 fine-tune VITS | **130 ms ✅ 同上管线** | 一次性训练 |

**关键判断：**
- 想"今天就听到"，用 174 说话人里挑一个接近的 → 立刻有，130ms。
- 想"就是我的声音"，两条路：
  - **零样本克隆**：10 分钟能试听，但延迟未验证，且多数克隆模型**不是流式**，首包可能要到 500ms+。
  - **微调 VITS**：要一次训练（几小时 GPU），但训完之后**完全复用现有的 130ms 管线**——这是唯一"低延迟 + 真自定义"同时成立的路径。

## 四、修正后的方案

```
L0 固定话术  : 用【同一个声音模型】离线预渲染 ~100 条 → 直读文件，~0ms
L1 任意文本  : 本地 VITS（微调版或 174 选 1）流式        → 130ms
L2 云端兜底  : edge-tts（音色会变，仅在本地不可用时启用，并语音告知"已切换音色"）
```

**核心原则：L0 和 L1 必须用同一个声音模型。** 这样才能做到"音色统一 + 延迟极低"。
edge-tts 从主力降为兜底，因为它是唯一会破坏音色一致性的环节。

## 五、风险与待验证

1. **采样率存疑**：模型元数据写 `sample_rate=8000`，但频谱分析显示 4kHz 以上仍有 4.35% 能量——8k 采样不可能有 4k 以上内容，说明元数据不准。**播放前必须听感确认**，否则语速/音调会错。已存 `tts-check.wav`。
2. **句级分块 vs 采样级流式**：当前是"整句算完再回调"，短句没问题，但长句（>10s）第一块会偏大。若发现长句首包变慢，需拆分句喂入。
3. **克隆模型延迟 [未验证]**：CosyVoice2 等未在本机测过，不能承诺 130ms 这个数字。
4. **音质**：29.8MB 的小模型音质明显不如边缘云 TTS，需实际听感评估是否可接受。

## 六、模型横评（换更好的模型，实测）

本机为 **CPU 推理**（sherpa-onnx pip wheel 不含 CUDA，实测 `provider="cuda"` 会打印
`Please compile with -DSHERPA_ONNX_ENABLE_GPU=ON` 并回退 CPU）。

| 模型 | 采样率 | 音色数 | 首包 | 总耗时 | RTF | 克隆 | 判断 |
|---|---|---|---|---|---|---|---|
| vits-icefall-zh-aishell3（现状） | **8 kHz** | 174 | 130 ms | 147 ms | 0.02 | ✗ | 快但电话音质 |
| **vits-melo-tts-zh_en** | **44.1 kHz** | 1（女） | **104 ms** | 766 ms | **0.18** | ✗ | ✅ 音质与延迟双赢 |
| kokoro-int8-multi-lang-v1_1 | 24 kHz | 103 | 1298 ms | 6397 ms | **1.28** | ✗ | ❌ CPU 跟不上实时 |
| zipvoice-distill-int8 | 24 kHz | 克隆 | 2009 ms | 2009 ms | 0.40 | **✓** | 仅适合离线预渲染 |

对比音频：`docs/bench/tts-compare.wav`（38.4 秒，四段带语音编号）

### 结论

- **默认音色换 MeloTTS（44.1 kHz）**：采样率提升 5.5 倍，首包还更快（104 vs 130ms），
  RTF 0.18 留有余量。代价：只有 1 个女声。
- **Kokoro 音色最多（103 个）但在 CPU 上 RTF 1.28** —— 生成 5 秒音频要 6.4 秒，不能用于实时对话。
  要用它必须换 GPU 构建（自编译 sherpa-onnx 或直连 onnxruntime-gpu）。
- **ZipVoice 可零样本克隆**（3 秒参考音即可复刻音色），但 2 秒延迟，只适合 L0 预渲染。

### 备选：vits-zh-hf-* 系列
`fanchen / theresa / echo / eula / keqing / bronya / zenyatta / doom` 等，各 114 MB、
22.05 kHz、单说话人。音质好于 aishell3 且速度快，适合"想要多个不同角色音色 + 实时"，
但每个音色是一个独立模型文件（体积累加）。

## 七、建议的下一步（30 分钟内可完成）

1. 听 `tts-check.wav` 确认采样率与音质。
2. 从 174 个说话人里扫一遍挑 3 个候选音色，生成样音给你选。
3. 你选定后，再决定是"选音色"还是投入"微调/克隆"。
