## 一、从实拍图提取到的设计语言

### 1.1 布局骨架

```
┌──────────┬──────────────────────────────────────────┐
│ 左侧栏    │  主画布                                   │
│ 248px    │  · 顶部无标题栏，内容居中                  │
│          │  · 大标题（28–32px，字重 400，非加粗）      │
│ Copilot  │  · 药物形输入框（全圆角，白底，带图标）     │
│ 搜索      │  · 药丸型分段控件（选中=黑底白字）          │
│ 创建      │  · 列表项：图标 + 主文本 + 小字元信息        │
│ 应用      │                                          │
│ ─────    │                                          │
│ 应用图标   │                                          │
│ ─────    │                                          │
│ 头像/设置  │                                          │
└──────────┴──────────────────────────────────────────┘
```

**关键手法**：大量留白 + 极小的信息密度 + 单一强调色（黑/白）。没有任何渐变、阴影堆叠、装饰线。

### 1.2 设计令牌（可直接落 CSS 变量）

| 类别 | 取值 | 用途 |
|---|---|---|
| 背景（画布） | `#f9f9f9` | 主区域 |
| 背景（侧栏） | `#f3f3f3` | 与画布微差，靠明度分层，不用边框 |
| 卡片/输入 | `#ffffff` | 输入框、列表 hover |
| 主文本 | `#1a1a1a` | 标题、正文 |
| 次文本 | `#6b6b6b` | 时间、元信息 |
| 分割线 | `#e5e5e5` | 仅用于必要的边界 |
| 强调（选中） | `#000000` 底 + `#ffffff` 字 | 药丸选中态 |
| 圆角 | 输入框 **999px**（药物形）；列表项 8px；卡片 12px | |
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32 | |
| 字号 | 标题 30px / 正文 14px / 元信息 12px | |
| 字重 | 标题 400（不加粗，靠字号拉层级）、正文 400、强调 600 | |
| 字体 | `"Segoe UI Variable", "Segoe UI", "Microsoft YaHei"` | |
| 动效 | 120–180ms ease-out；仅位移与透明度 | |

> 反直觉但重要：**标题不加粗**。Copilot 靠字号和留白建立层级，加粗反而显得廉价。

### 1.3 我们没能拍到的部分

Copilot 的**语音会话界面**（点击麦克风后）没有在实拍里出现，需要登录态。
所以下面关于"聆听态/播报态"的形态是**基于其设计语言的外推**，不是照抄；实现后需再对一次截图。

## 二、字幕（R10）：必须与语音同步

### 2.1 为什么不能"整段生成完再显示字幕"

语音是流式的，字幕必须同速。否则出现"已经听到第三句，字幕还停在第一句"。

### 2.2 同步模型

```
LLM 流式 delta ──▶ 按标点切句 ──▶ ① 字幕立刻上屏（整句灰显）
                                   ② 该句送 TTS 合成
                                   ③ 音频开始时整句转亮 / 逐字高亮
                                   ④ 音频播完转"已读"态（颜色变暗，不复述）
```

**关键约束**：
- **切句即发**：不等整段完成。第一句落地（约 0.7s）就同时出字幕和音频。
- **句级精确、字级估算**：我们的 TTS（sherpa-onnx bronya）不返回词级时间戳，但**每句音频时长是已知的**（合成完就知道），因此：
  - 句边界：**精确**（音频时长驱动）
  - 句内逐字高亮：按字数的线性插值估算（误差在校验后接受）
- 若后续换成能返回词边界的 TTS（如 edge-tts 的 word boundary 元数据），把字级估算换成真实时间戳，接口不变。

### 2.3 显示规则

| 状态 | 样式 |
|---|---|
| 未播（已上屏，等待中） | 次文本色 `#6b6b6b` |
| 正在播 | 主文本色 `#1a1a1a` + 逐字高亮（高亮字 `#000`，其余 `#8a8a8a`） |
| 已播 | `#9a9a9a`，保留最近 2 句，更早的淡出 |
| 被打断 | 保留已播部分，末尾加一个"·"并停止高亮 |

### 2.4 位置与可读性

- 位置：**小窗内部**，位于状态指示下方，距窗口底边 12px。
- 单行最大宽度 **360px**（与右下角小窗一致），最多 **3 行**，超出时旧句上移淡出。
- 字号 15px（小窗里不需要 16px 大字号，反而挤），行高 1.55。
- **可关闭**：设置里"显示字幕"，关闭后仅保留状态指示——但默认开启。

### 2.5 用户说的话也要显示

不只显示助手输出：用户说话时，ASR 的部分结果实时上屏（灰色斜体），final 后转正体并锁定。
这是"对话感"的一半来源——Copilot 语音模式也是这个做法。

## 三、形态：右下角小浮层（R12）

> **明确边界：不要大窗口。** 不用居中面板、不用全屏遮罩、不用可拖拽的大卡片。
> 它就是一块常驻在右下角的小玻璃，不遮工作内容。

### 3.1 为什么是右下角

- 屏幕上"最不用于工作"的区域：任务栏右侧、通知区上方
- 与 Windows 通知、Copilot 侧边呼出习惯一致
- 视线余光可及，不需要移动注意力

### 3.2 生命周期：平时没有窗口

**这是本方案最重要的一条**：应用启动后**不创建任何窗口**，只有托盘图标在后台跑。

```
进程启动
  └─ 只有托盘图标 + 后台唤醒监听（无任何可见窗口）

用户点击托盘图标 ──┐
语音唤醒命中 ──────┴─▶ 创建/显示小窗（右下角滑入）
                        ↓
                     聆听 → 思考 → 播报
                        ↓
            播报结束后静默 8s（可调）
                        ↓
                   窗口隐藏，回到"无窗口"状态
```

- 无对话时：**屏幕上什么都没有**，不占位、不常驻、不穿透（也就不需要鼠标穿透）。
- 触发方式只有两种：**托盘图标点击** / **语音唤醒**（唤醒可关闭，关闭后只剩托盘与热键）。
- 退出对话：自动（静默 8s）、按 `Esc`、或点小窗右上角关闭。

### 3.3 尺寸与定位

| 项 | 取值 |
|---|---|
| 出现时 | **380 × 自适应**，高度 88 → 最大 **420** |
| 距屏幕右下角 | 右 20px，下 20px（按**工作区**算，避开任务栏） |
| 圆角 | 16px（比 Copilot 输入框的 999px 收敛一点，小尺寸下全圆角显得碎） |
| 阴影 | `0 8px 28px rgba(0,0,0,.10)`，仅一层，不做多层叠加 |
| 背景 | `rgba(255,255,255,.92)` + `backdrop-filter: blur(20px)` |

**随内容长高，不长宽**。宽度固定 380——宽度变化会让窗口边缘不停跳动，很干扰。

### 3.4 弹出与收起

- 弹出：从右下角**向上滑入 12px + 淡入**，160ms ease-out
- 收起：反向，120ms，然后**隐藏**（不是缩成胶囊）
- **不做**缩放动画（缩放会让人以为窗口在抢注意力）

### 3.5 不打断工作的三条要求

窗口只在"用户主动叫我"时存在，所以**不需要鼠标穿透**。真正要守住的是这三点：

1. **音频唤醒不抢焦点**：用户打字时被唤醒，窗口用 `showInactive()` 出现，光标不跳走；
   托盘点击是明确的操作意图，用 `show()` + 聚焦。
2. **不入任务栏**：`skipTaskbar: true`，只留托盘图标。
3. **说完就走**：静默 8s 自动隐藏。**赖在屏幕上不走的小窗，比没有小窗更烦人。**

> 实现取舍：隐藏（hide）而不是销毁（destroy），下次唤出 <100ms；
> 代价是渲染进程常驻内存（约 60–100MB）。若用户在意，可设置"空闲 5 分钟后销毁"。

### 3.6 托盘菜单

托盘是唯一的常驻入口，菜单至少要有：

| 项 | 说明 |
|---|---|
| 唤醒 / 开始对话 | 等同点击图标 |
| 语音唤醒 | 勾选开关（R5），关闭后释放麦克风 |
| 语音播报 / 语音确认 | 两个独立开关（§2.2） |
| 显示字幕 | 勾选开关（R10） |
| 设置… | 打开配置页（模型/权限/音色） |
| 退出 | 真正结束进程 |

**托盘图标要能表达状态**：待命=灰、监听中=蓝、播报中=波形微动。
否则用户不知道后台在不在听——这是隐私相关的必要反馈。

### 3.7 状态机与视觉

| 状态 | 尺寸 | 视觉 |
|---|---|---|
| **HIDDEN** | 无窗口 | 只有托盘图标（待命灰） |
| LISTENING | 380×88 | 蓝点 + 环形呼吸 + ASR 部分结果 |
| THINKING | 380×88 | 三点跳动（300ms）+ 白描文本 |
| SPEAKING | 380×自适应 | 波形条（真实电平）+ 当前句高亮字幕 |
| NEED_CONFIRM | 380×auto | 底部浮出确认条：动作描述 + 「允许 / 拒绝」 |
| ERROR | 380×88 | 红点 + 一行说明，5s 后回 HIDDEN |

> 播报时的波形条要用**真实音频电平**驱动，不用随机动画——假的在静音时会"假装在说话"，很出戏。

### 3.8 资源策略：默认隐藏，按需销毁（R14）

隐藏的代价是渲染进程常驻内存（约 60–100MB）。所以定了两级策略：

| 策略 | 触发 | 动作 |
|---|---|---|
| **默认** | 对话结束 | `hide()`，下次唤出 <100ms |
| **销毁** | 见下表三种情况 | `destroy()`，释放渲染进程，下次唤出约 200ms |

#### 销毁触发条件

| # | 条件 | 判据 | 为什么 |
|---|---|---|---|
| 1 | **全屏独占应用运行中** | `SHQueryUserNotificationState` 返回 `RUNNING_D3D_FULL_SCREEN` / `PRESENTATION_MODE` / `BUSY` | 打游戏时任何置顶窗口都是干扰；同时避免和游戏抢 GPU/内存 |
| 2 | **系统内存紧张** | 可用物理内存 < 1.5GB（本机 31.2GB，约 5%）或 < 10% | 不能让一个语音助手成为压垮系统的那根稻草 |
| 3 | **自身内存异常** | 本进程 RSS > 400MB | 疑似泄漏时主动重建，比一路涨到崩好 |

> 用 `SHQueryUserNotificationState` 而不是维护"游戏进程白名单"：
> 它是 Windows 官方给"是否该弹通知"的信号，全屏 D3D 游戏、演示模式、锁屏都覆盖，
> 且**免维护**——新游戏不需要改配置。已在本机验证可正常调用（返回 `QUIET_TIME`）。

#### 销毁后的行为

- **托盘图标保留**（在主进程，不依赖渲染进程）
- **唤醒监听保留**（音频在主进程）
- 下次唤出时**重建窗口**，位置与状态从上次恢复
- **不主动重建**：退出游戏后不自动弹窗，只在用户下次唤出时创建
  （打完游戏突然冒出一个小窗，比不出现更糟）

#### 游戏模式的附加行为（建议开启，可配置）

全屏游戏期间**暂停语音唤醒**，理由两条：
1. 游戏常占用音频设备，采集容易抢麦或失败
2. 部分反作弊对常驻音频采集敏感，没必要去触霉头

菜单里给一个"全屏应用时暂停唤醒"的开关，默认**开**。

#### 轮询

- 30s 一次，`SHQueryUserNotificationState` 调用 <1ms，内存查询更便宜
- 仅在 HIDDEN 态轮询；窗口可见期间不检查（正在对话，不该被销毁）

### 3.9 多显示器与 DPI

- 默认出现在**主显示器**右下角；用户可设置"跟随当前活动窗口所在屏"
- 一切按 `workArea`（不含任务栏）计算，而不是 `bounds`
- 位置计算走 **物理像素 → DIP 换算**，否则 150% 缩放下会偏出屏幕
  （本项目已实测 144 DPI，这条必踩）

### 3.10 和 Copilot 的关系

我们借的是它的**视觉语言**（见 §1.2 令牌），不是布局。
Copilot 主壳是"左侧栏 + 大画布"，那是搜索/工作台形态；我们要的是它的
浮层形态（它自己安装包里也有 `copilot_overlay_*.pak`）。
**小窗配色、圆角、字体、留白比例照抄；布局按右下角浮层重新设计。**

## 四、与权限系统的衔接（P3）

确认卡片必须能在**不打断对话**的前提下出现：

```
助手："要删除这三个文件，确认吗？"
        ↓
卡片底部浮出：[ 删除 3 个文件 ]  [ 允许 ] [ 拒绝 ]
        ↓ 语音确认走完整短语匹配（R2 的闸门）
        ↓ 若语音确认已关闭 → 只能点按钮
```

按钮优先级：**键盘可达**（Enter=允许，Esc=拒绝），不能只有鼠标。
