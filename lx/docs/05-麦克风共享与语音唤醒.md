# 麦克风共享与语音唤醒（实测验证）

> 问题：能否做到"常驻语音唤醒，但不占用麦克风、不影响其他应用"？
> 结论：**在 Windows 上可以，而且是默认行为**——前提是不使用独占模式。

---

## 一、实测验证（本机）

`tools/mic_share_check.py` 同时启动两个进程，各自打开麦克风录音 4 秒：

| 进程 | 采样数 | RMS | 峰值 | 结果 |
|---|---|---|---|---|
| A | 64000 | -49.6 dBFS | 0.0127 | ✅ 正常采集 |
| B | 64000 | -49.6 dBFS | 0.0127 | ✅ 正常采集 |

两个进程**同时**拿到了完整、一致的音频流，互不阻塞、互不报错。
说明 Windows 音频栈默认走 **WASAPI 共享模式**：多个客户端可以并发采集同一设备。

**这正是"像手机助手一样不抢麦克风"的技术基础。**

---

## 二、为什么 Windows 天然支持（和手机的差异）

| | 手机（Android 10+） | Windows |
|---|---|---|
| 并发采集 | 允许，但有仲裁：后台应用可能收到静音 | 允许，**所有共享客户端收到相同信号** |
| 隐私提示 | 状态栏绿点 | 托盘"麦克风使用中"图标 |
| 独占 | 应用可申请独占（较少） | 应用可申请 **WASAPI Exclusive**，此时其他应用采集失败 |

**关键推论**：在 Windows 上，"不抢麦"不是需要额外实现的功能，而是**默认状态**。
反而"抢麦"才需要刻意去做（申请独占模式）。所以我们的设计原则是：

> **永远只用共享模式，永不申请独占。**

---

## 三、真正会出问题的四种情况（必须处理）

### 3.1 其他应用抢先用了独占模式
部分 DAW、老录音软件、某些会议软件会申请独占。此时：

- 我们的采集会失败（**不是我们导致别人失败，而是别人导致我们失败**）
- 处理：捕获失败 → 自动降级为"仅热键触发"，并在 HUD 上提示"麦克风被其他应用独占"

### 3.2 蓝牙耳机的 A2DP↔HFP 切换（最容易被忽略）
用蓝牙耳机时，一旦有应用打开麦克风，系统会从 A2DP（高音质）切到 HFP（通话质量），**输出音质骤降**。

这是手机同样存在的问题，但桌面场景更明显，因为用户常在听音乐。

**对策**：
- 唤醒词采集**固定绑定内置麦克风阵列**（Realtek），不用蓝牙耳机的麦克风
- TTS 输出走当前默认输出设备
- 设置里允许用户手动指定"唤醒用麦克风"

### 3.3 设备驱动不支持并发
少数 USB 麦克风驱动限制并发流。检测方式：启动时试探性开流，失败则提示。

### 3.4 系统隐私开关 / 企业策略
`设置 → 隐私 → 麦克风` 关闭时，采集直接失败。启动自检要给出明确指引。

## 四、资源占用设计（常驻监听的代价）

| 项 | 设计 | 实测依据 |
|---|---|---|
| 采样率 | 16 kHz 单声道 | 唤醒词模型标准输入，省 60% CPU |
| 帧长 | 20 ms | 兼顾延迟与开销 |
| VAD + KWS | 常驻，仅命中后启动完整 ASR | 避免全程跑大模型 |
| 预期 CPU | < 2%（单核） | 待实现后实测 |

### ⚠️ 实测发现的一个真问题：麦克风增益太低

本机麦克风阵列在安静环境下 RMS 仅 **-49.6 dBFS**（约 -50dB，很微弱）。这是笔记本阵列的典型值。
如果直接喂给唤醒词模型，**召回率会很低**（模型训练集是正常语音电平）。

对策：采集后做 AGC（自动增益），目标电平 -26 ~ -20 dBFS，并加噪声门限，避免把底噪也放大。
这一条不做，唤醒词会觉得"时灵时不灵"。

## 五、实现架构

```
┌─────────────────────────────────────────────┐
│ 唤醒服务（单一常驻进程，绝不多进程开流）      │
│                                             │
│  WASAPI shared · 16kHz · mono · 20ms 帧      │
│        │                                    │
│        ├─ AGC（-50dB → -22dB 目标）          │
│        ├─ VAD（判断是否有人声）               │
│        └─ KWS（唤醒词，<2% CPU）              │
│                │ 命中                        │
│                ▼                            │
│        通知 Orchestrator → 进入 LISTENING    │
└─────────────────────────────────────────────┘
```

**必须遵守的三条**：
1. **单进程单流**：多个模块需要音频时走内部管道，不各自开流（否则设备占用计数和 AGC 状态会乱）
2. **不改设备格式**：不修改系统采样率/位深，重采样由我们自己做（改系统设置会影响其他应用）
3. **可随时释放**：用户可一键"关闭唤醒"，立即释放采集流

## 六、与"手机助手"体验的对齐点

| 手机行为 | 我们的实现 |
|---|---|
| 说唤醒词直接响应 | KWS 命中 → 提示音 + HUD 亮起 |
| 其他应用仍能录音 | 共享模式，天然支持（已实测） |
| 通话中不抢麦 | 检测设备被占用 → 自动降低优先级/暂停 |
| 状态栏显示麦克风使用中 | Windows 托盘图标，不隐藏（保持透明） |
