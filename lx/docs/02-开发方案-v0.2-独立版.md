# Computer-Use 语音助手 · 开发方案 v0.2（独立版）

> **v0.1 作废。** 原方案把 DSH NEXT 当外挂大脑，现改为：**独立软件，自带 agent，只从 dsh-computer-use 复制 computer-use 能力。**
> 本机已拉取参考仓库：`refs/dsh-computer-use`（MIT）、`refs/dsh-desktop`（MIT）。

---

## 一、结论先行

1. **"单独复制一个只有 computer-use 的 dsh" 是可行的，而且成本极低。**
   实测 `dsh-computer-use`：**MIT 协议、零 npm 依赖、纯 ESM**。除 `src/index.js` 里一次 `ctx.tools.register()` 外，所有代码不碰 cordis。
   我们要的东西正好全在可移植区：25 个工具定义、NDJSON 桥、109KB 的 `cua.ps1` Windows 原生后端。

2. **我们要自己写的只有三块**：agent loop（~300 行）、语音链路、悬浮窗。没有第四块。

3. **风险从"DSH API 403"变成"自研 agent loop"——从不可控变可控。**
   不再需要 token、不再受 DSH 版本升级影响、不再有进程间协议反推。

## 二、可移植性实测（这是本方案的地基）

### 2.1 依赖分析（逐个文件核实）

| 文件 | 大小 | 外部依赖 | 判定 |
|---|---|---|---|
| `src/bridge.js` | 15KB | **仅 `node:child_process` + `node:url`** | ✅ 直接可用 |
| `src/tools.js` | 46KB | 仅 `./schema.js` | ✅ 直接可用 |
| `src/schema.js` | 10KB | 无 | ✅ 直接可用 |
| `src/format.js` | 14KB | 无 | ✅ 直接可用 |
| `src/config.js` | 10KB | 无 | ✅ 可用（改默认路径） |
| `src/indicator.js` | 10KB | `./bridge.js` | ✅ 可用（屏幕操作指示器） |
| `src/native/cua.ps1` | **110KB** | 无（Windows PowerShell 5.1 自带 System.Drawing / UIAutomationClient） | ✅ 直接可用 |
| `src/native/indicator.ps1` | 42KB | 无 | ✅ 直接可用 |
| `src/index.js` | 22KB | **cordis `ctx.tools.register()` / `ctx.effect()`** | ❌ 丢掉，写 20 行适配器替代 |
| `src/skill.js` | 4KB | 写 `~/.dsh` 路径 | ❌ 丢掉 |

**package.json 里没有 `dependencies` 字段。** 整个插件零三方包——这意味着抠出来不会有依赖地狱。

### 2.2 25 个工具（语音场景要裁剪）

原生全量：`request_access` `list_apps` `list_windows` `get_app_state` `screenshot` `zoom` `open_application` `left_click` `double_click` `triple_click` `right_click` `middle_click` `mouse_move` `left_click_drag` `scroll` `type` `key` `hold_key` `set_value` `select_text` `perform_action` `wait` `read_clipboard` `write_clipboard` `stop_computer_control`

> ⚠️ **语音场景只喂 10–12 个，不要全给。**
> 理由：① 25 个 schema 常驻上下文，每次请求多烧 token；② 语音指令短且欠明确，工具越多模型选错概率越高。
> 建议保留：`screenshot` `get_app_state` `list_windows` `open_application` `left_click` `type` `key` `scroll` `set_value` `wait` `read_clipboard` `write_clipboard`。
> 其余（zoom / triple_click / hold_key / drag…）做成"高级模式"按需开启。

### 2.3 原生后端的关键约束（踩了就全程错）

- **必须是 Windows PowerShell 5.1**（`powershell.exe`），不是 pwsh 7——`UIAutomationClient` 在 5.1 宿主才开箱可用。
- 脚本必须带 **UTF-8 BOM**，否则 5.1 按 ANSI 读，中文注释破坏语法。
- 必须 `SetProcessDPIAware()`：实测 150% 缩放下不调用，截图是 1707x1067 而 UIA/窗口坐标是 2560x1600，**坐标映射全错**。
- stdout 是 NDJSON 专线，**禁止任何 Write-Host / Verbose 污染**；诊断只能走 stderr。
- 协议**串行**：超时无法判断迟到响应归属 → 直接 kill 进程，下次调用重启，**绝不猜**。

### 4.1 适配器（这就是全部"移植工作量"，约 60 行）

```ts
// packages/cua/adapter.ts
import { NativeBridge } from './bridge.js'
import { createToolDefinitions } from './tools.js'
import { assertArgs, coerceArgs } from './schema.js'

export class CuaToolkit {
  #bridge: NativeBridge                      // 自带 串行队列 / 超时换进程 / 自愈
  constructor(opts: { scriptPath: string; cwd: string; timeoutMs?: number }) {
    this.#bridge = new NativeBridge(opts)
  }
  async warmup() { await this.#bridge.ensureStarted() }   // ★ 启动即预热

  tools() {                                   // → OpenAI function-calling schema
    return createToolDefinitions({ /* 裁剪后的白名单 */ })
      .map(t => ({ type: 'function', function: { name: t.name, description: t.description, parameters: t.inputSchema } }))
  }

  async invoke(name: string, rawArgs: unknown) {
    const def = this.#defs.find(d => d.name === name)
    const args = coerceArgs(def, assertArgs(def, rawArgs))   // 参数校验 + 无损宽化
    return await this.#bridge.call(def.nativeMethod ?? name, args)
  }
}
```

> `NativeBridge` 已经内置了我们要手写的全部脏活：`ensureStarted()` 启动握手、`call(cmd, args, {timeout, signal})`、`probe()`、`dispose()`、崩溃重启计数。**这是本项目最大的时间节省点。**

### 4.2 agent loop（自研，约 300 行）

```
loop:
  stream = llm.chat({ messages, tools, stream: true })
  for chunk in stream:  ├─ 文本 → 送 TTS 队列（按句切分）
                        └─ tool_call → 收集
  if 无 tool_call: break
  for call in tool_calls:
      if 高风险(call): 暂停 → HUD 请求确认 → 拒绝则回填 tool_result 说明
      result = await cua.invoke(call.name, call.arguments)
      注入 tool_result（截图结果做压缩：只留最近 1 帧 + 元素摘要）
  if steps > N: 强制收尾并汇报
可中断点：每个 await 前检查 abortSignal；用户说话 → abort → 清空 TTS 队列
```

**上下文管理是这里的隐藏难点**：每次工具调用都返回截图，多步任务会把 context 撑爆。策略：只保留**最近一帧截图** + 历史步骤降级为文字摘要（`"第2步：点击了'发送'按钮"`）。

## 五、语音链路（与 v0.1 一致，但改为零 Python）

| 环节 | 选型 | 理由 |
|---|---|---|
| 采集 | Electron `AudioWorklet` 16k PCM | 免 ffmpeg（v0.1 里那个 ffmpeg 依赖可以去掉） |
| VAD | `sherpa-onnx` 系列自带的 VAD（silero） | 与 ASR 同一套运行时，不引入第二个推理引擎 |
| ASR | **sherpa-onnx-node**：Paraformer 流式中文 / Whisper-turbo 兜底 | **Windows 预编译 .node，不需要 Python**（DSH 自己也用它），首字 ~200ms |
| TTS | **`msedge-tts`（纯 JS 移植）** 流式 | 免 Python、免 key、中文自然、首包 ~200ms；离线兜底用 sherpa-onnx 的 VITS/kokoro |
| 唤醒 | 全局热键（按住说话）优先；openWakeWord 后置 | 误触是体验杀手 |

> **重要**：v0.1 里"要装 ffmpeg / pnpm / Python"三条全部作废，只剩装 pnpm。

**延迟预算**：VAD 尾点 300–500ms + ASR final 150–250ms + LLM 首 token 300–600ms + TTS 首包 150–300ms ≈ **0.9–1.6s**。
计数技巧不变：允许"占位播报"先行，把**感知**延迟压到 0.5s。

## 六、语音 × computer-use 的融合设计（本项目真正的差异化）

光有"语音转文字再调工具"是最低级的做法。要让它像人，得补三件事：

### 6.1 指代消解（voice deictic）
说"**点这个**""**右边那个框**"——纯文本 agent 无法处理。方案：
- 说话瞬间抓一帧截图 + 鼠标位置；
- 把"当前鼠标附近的可交互元素"标注序号叠在截图上（`indicator.ps1` 已能画）；
- 让模型在**编号**上指认，而非猜坐标。

### 6.2 动作白描（narration）
不播"正在调用 left_click"，播"**我正在点'发送'**"。
实现：工具返回的 `get_app_state` 元素名 + 动作类型 → 模板生成。成本极低，体验差异极大。

### 6.3 高风险确认：**必须物理确认，不能用语音确认**
"要删除这 3 个文件，确认吗？"——如果用户说"确认"就执行，那**任何播到音箱的声音、任何路过的人声都能触发删除**。
规则：高风险动作 → HUD 弹卡片 → **必须鼠标点击或按 Enter**。这是安全底线，也是和"玩具 demo"的分界线。

风险分级（数据驱动，非硬编码）：
| 级别 | 特征 | 处理 |
|---|---|---|
| 低 | 打开应用、滚动、截图、读剪贴板 | 直接执行 + 白描 |
| 中 | 输入文本、点击提交类按钮 | 执行 + 可撤销提示 |
| 高 | 删除、发送消息、支付、改设置、密码框 | **阻塞 + 物理确认** |

### 6.4 语音友好工具层改造
- `open_application` 加中文别名表（"飞书"→ Feishu.exe，可用本机 `fairy/exe_index.json` 那个 1416 条 exe 索引直接复用！）
- `type` 前自动聚焦目标 + 清空，避免追加到旧内容
- 所有动作后**自动验证**（再截一帧对比），失败重试 1 次并口头报告
